# 学术文本润色与去 AI 味（Paper Polish）

本技能处理**已经写好的文本**：输入一段或一篇稿子，输出改得更像资深学者手笔、且意思一字不改的版本，
外加一份能核对的改动记录。它不生成内容，不替作者下结论，不补事实。目标不是规避检测，而是把文字写到
顶刊审稿人读起来不起疑的水准：论断干净、每段有具体物、没有机器写作的统计指纹。

## 何时以及如何使用本技能

0. **识别输入**：文本形态（`.tex` / Markdown / 纯文本 / 粘贴段落）、语言（中/英，机检自动识别）、体裁
   （正文、摘要、回复信、信函、方案）、目标 venue（决定阈值校准语料与时态惯例）。体裁决定哪些条款豁免
   （见"体裁规则"）。
1. **选模式**（用户没说就按下表的触发词判断；拿不准先做体检，报告里给出建议模式）。
2. **校准阈值**：用户能给目标刊物 2–3 篇已发表论文时，先跑 `style_baseline.py` 生成
   `style_baseline.json`；有作者自己的旧稿时同法提取作者基线——稿件向作者靠，不向通用学术腔靠。
3. **执行**：先跑 `stylecheck.py` 拿到基线报告，再按模式改；改完复跑，直到零 FAIL（深度模式另要求
   零 note 中的"paragraph with nothing concrete"）。
4. **交付**：改后文本 + 改动清单（每条标规则编号）+ 机检前后对比 + 待补事实清单 + 未改之处与理由。
   格式见 `references/polish-protocol.md`。

## 三种模式

| 模式 | 触发词 | 做什么 | 不做什么 | 产出 |
|---|---|---|---|---|
| **体检** | 检查一下、有没有 AI 味、过一遍文体 | 跑 `stylecheck.py`，按项号逐条解释命中处，给出建议模式 | 不改一个字 | 报告 + 反向大纲 |
| **润色** | 润色、改顺、去 AI 味、像人写的 | 句级改写：标点、连接词、强调、命名与缩写、节奏、禁用词、对冲；保留作者口吻 | 不动段落结构，不删句子（除纯填充句） | 改后文本 + diff + 改动清单 |
| **深度去 AI 味** | 重写、太空、审稿人说读不出贡献 | 段级：反向大纲、从文本反推事实清单、删减配额 10–15%、每段补具体物指向、因果句、引用评价 | 不编造事实；空洞处留占位 | 改后文本 + 改动清单 + 待补事实清单 |

深度模式的"事实清单"从文本自身反推：把每句话能指到的数字、公式号、表图号、引用、结论列出来，指不到
任何事实的句子就是填充，进删减配额；一段话里没有任何事实的，留 `〔待补事实：此处需要 ___〕`，由作者补。

## 四条不变量（任何模式都不违反）

1. **不改事实、数字、引用与 claim 强度**。"显著优于"改成"gap 降低 2.1 个百分点（表 4）"只在原文或附带
   材料已有这个数字时才做；没有数字就改成"优于"并记入待补事实，不得自己填数。收窄 claim 属于作者
   决策，润色只标出过度声称处，不替作者收窄。
2. **不新增内容**。不补背景、不加过渡段、不加小结句。
3. **每处改动可指到规则编号**（`references/style-rules.md` 的条款号或 `stylecheck.py` 的项号 14–27）。
   说不出依据的改动不做。
4. **交付可核对**：diff（或逐段对照）、改动清单、机检前后 FAIL/note 计数。作者能在五分钟内接受或回退
   任何一处改动。

## 规则摘要（全文见 `references/style-rules.md`，正例库见 `references/style-rewrite-examples.md`）

- **表层**（标点与词汇指纹，机检可拦）：句首连接词每节至多 1–2 处；正文不用分号、句中冒号、破折号
  插入语；句中不加粗不斜体强调，段首引导词用 `\paragraph{}`；命名与缩写有预算且不造词；禁用词与
  替换表；句长有长有短、三连排比限量、段尾不写小结句、强化副词与泛动词限密度；摘要单段；时态按
  venue 惯例全文统一。
- **深层**（内容空洞，机检只能拦一部分）：读者是熟悉全部基线的审稿人，常识不解释；方法与实验段每段
  至少一项具体物；结果句后面跟机制解释句并指向背书证据；一处引用不超过 4 篇且逐篇有评价；定量声明
  必须带数字与出处。
- **反防御性写作**：每个结论句至多一个限定词，限定必须可判定，无信息免责句删除，过度声称的唯一修法
  是收窄到证据边界并给数字（润色只标出，由作者定），适用边界集中进 limitations。

## 体裁规则

| 体裁 | 豁免 | 仍然适用 |
|---|---|---|
| 论文正文、摘要、方案 | 无 | 全部条款 |
| rebuttal 回复信 | 礼节句式、编号冒号、加粗定位（体裁结构） | 命名与缩写纪律、禁用词、对冲、节奏 |
| cover letter | 首末段礼节句的标点与加粗；期刊名斜体；Harvard 多引文列表的分号（加 `% style-exempt`） | 其余与正文同标准 |
| 中文文本 | 无 | 标点与词表自动切换为中文：不用"——"与句中"："，不造"××感知/××驱动"式新词，"可能/或许"不堆叠 |

## 机检：`stylecheck.py`（实现与阈值见 `references/stylecheck.md`）

```
python stylecheck.py sections/*.tex                 # LaTeX 分节文件
python stylecheck.py draft.md                       # Markdown / 纯文本（**加粗** 按句中强调计）
python stylecheck.py paper/zh-draft.tex --zh        # 中文（CJK 占比超过三成时自动识别）
python stylecheck.py sections/*.tex --baseline style_baseline.json
```

14 项：14 散文分号 / 15 句首连接词 / 16 禁用词 / 17 对冲预算与堆叠 / 18 命名与缩写预算 / 19 句中冒号 /
20 破折号 / 21 句中强调与 `\paragraph` 预算 / 22 摘要单段 / 23 句长节奏与三连排比 / 24 强化词、泛动词、
抽象名词密度 / 25 段落具体性与段尾小结 / 26 簇引用 / 27 反向大纲。合法例外在该行加 `% style-exempt`
（数学与伪代码里的分号冒号、引用他人原文、术语首次定义的强调）。项号与家族仓库的 `check.py` 连续
（那边 1–13 是一致性与投稿限制，28–29 是投稿包与匿名稿），`check.py` 直接导入本脚本。

## 交付格式（细则与示例见 `references/polish-protocol.md`）

1. 改后文本（同格式、同文件名加 `-polished`，或直接给可粘贴的段落）。
2. 改动清单：行号 / 原文 / 改后 / 规则编号 / 一句理由。
3. 机检前后对比：FAIL 与 note 的条数，以及剩余项的说明。
4. 待补事实清单（深度模式必有；润色模式有则列）。
5. 未改之处与理由：机检命中但判断为合法例外的行（已加 `% style-exempt`）。

## 交付前自检清单

- 四条不变量逐条核对：数字、引用、claim 强度与原文一致；没有新增句子；每条改动有规则编号；diff 可读。
- `stylecheck.py` 复跑零 FAIL；豁免行都带 `% style-exempt` 且理由成立。
- 体裁对了：回复信与信函没有被按正文标准误改；中文文本走了中文词表。
- 作者口吻保留：没有把作者的用词习惯替换成本技能的习惯；时态全文统一。
- 深度模式：反向大纲连读能讲通；删减量在 10–15%；待补事实清单逐条写明需要什么。
- 诚实边界已说明：文体规则显著降低但不能消除 AI 痕迹，终稿建议作者人工通读；AI 辅助披露按目标
  venue 政策处理。

## 与家族技能的关系

本技能是 `SKILLs-Generated`（`opt-paper-*`）与 `SKILLs-ML-Paper`（`ml-paper-*`）两组科研流水线的**文体
层**，三组装在同一个 skills 目录时自动衔接：

- **manuscript 技能（写稿）**：起草时引用本技能的规则写第一遍，每写完一节跑 `stylecheck.py`；三轮修订
  的第 2 轮调用本技能的润色模式做 final sweep；生成的 `check.py` 导入本技能的 `stylecheck.py`。
- **rebuttal 技能与投稿包**：按"体裁规则"调用，只用命名、禁用词、对冲与节奏条款。
- **proposal 技能**：方案期的命名预算与本技能"命名与缩写纪律"同源。

单独使用时不需要任何家族技能，也不需要项目契约文件。
